## 后端缺陷：PublishAppVersion 发布失败（已读源码+实查确认）
- 现象：后台发 android 版本报 409 `current release changed, build number did not increase, or release already exists`。
- 校验位置：`apps/admin/internal/data/data.go:785 PublishAppRelease`（事务内读 `t_starcore_app_version`）。
- 三条 ErrConflict 触发条件（后端合并成同一句）：
  1. 乐观锁：`expected_release_id` 必须 == 当前 starcore 行 id（`!hasCurrent && expected!=""` 或 `hasCurrent && expected!=currentID`）。
  2. 构建号严格递增：`build_number <= 当前 build`。
  3. 版本不能回退：`compareAppVersion(新,当前) < 0`。
  4. 唯一键重复插入：`isDuplicateError`。
- **关键 bug**：取"当前版本"的 SELECT `WHERE platform=?` **未过滤 status**。disable 后的版本 starcore 行 status=2 但仍存在，前端因 admin 无 active 传空 expected → 与后端期望 id 对不上 → 永远 409。修复：SELECT 加 `AND status=1`。
- 当前 android 实际状态（2026-11-05 实查）：无 active；最近 `rel_bd2f4061…` disabled v1.10.2 build571。用户填 1.1.5<1.10.2 属版本回退也被拦。
- 待确认：是否改后端 SELECT + `expected_release_id` 取最新一条 id（双保险）。未动代码，等用户决定。
