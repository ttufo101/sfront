## 订单管理 / 人工审核 切换不刷新（已修复并部署）
- 现象：侧栏「订单管理」(`/orders`) 与「人工审核」(`/orders?payment_status=manual_review`) 之间切换时，右侧列表内容不刷新，人工审核视图常显空白。
- 根因：二者 pathname 同为 `/orders`，`App.tsx` 仅一条 `<Route path="/orders" element={<OrdersPage/>}>`，React Router 在仅 query 变化时**不重挂载**组件。`OrdersPage` 把 URL 的 `payment_status` 仅用于 `useState` 初值（只在首次挂载生效），`useXrpcQuery('ListOrders', params)` 的 key 依赖 `params`，`params` 不变则不重发请求 → 列表冻结在首屏视图。
- 修复（`src/features/orders/pages/OrdersPage.tsx`）：
  - 新增 `useEffect` 监听 `urlPaymentStatus = searchParams.get('payment_status')`，变化时把 `filter` 重置为 `{...emptyFilter(), payment_status}`、`params` 重置为 `{page:1,page_size,payment_status?}` 并 `setDetail(null)`；用 `useRef(firstRun)` 跳过首次挂载避免重复请求。手动改筛选 Select / 点「人工审核」快捷筛选（只改内部 state、不动 URL）不会触发该 effect，无回环。
  - `PageHeader` 标题随视图变化：`manual_review`→「人工审核」，否则「订单管理」。
- 验证：`npx tsc --noEmit` 0 错、`vite build` 成功（新包 `index-CdtLVPW8.js`）；已 `scp` 部署 develop-tg `/opt/starland-admin-web` + `openresty reload`，bundle 含「人工审核/订单管理」。
- 说明：导航高亮逻辑（`AdminLayout.tsx:41-43`）本身正确（按 pathname+search 判定），截图里「订单管理」浅灰为普通/悬停态，非 bug，未改动。
- 经验：同一组件用 query 区分"子页面"时，必须在组件内 `useEffect` 同步 query→state，或给路由 `element` 加 `key={location.search}` 强制重挂载，否则状态/查询不刷新。

## 诊断日志下载 404（已修复并部署）⚠️ 同类 bug 复盘
- 现象：反馈详情里点「下载日志」(`GET /api/v1/log-files/{file_id}`) 报 HTTP 404（截图工单 `diag_52e2d8ac16e6460b83aabc4ab3b18053`, file_id `eb00fa2e-...`）。
- 根因（与 2026-10-28 反馈图片 404 同源，但 logs 路径当初漏改）：
  - 后端 `fileupload/internal/server/router.go:23` 公共 `logs` 处理器 `NewFileHandler(..., "", false)` → `allowServiceBypass=false`；`logs.Download`→`download(c, ownerRestricted=true)`（Kind≠AppRelease）。管理员（非上传者）跨 owner 取他人日志 → 代码 `OwnerUID(info)!=principal.UserID` 返回 404；且 `serviceTokenBypassesOwner` 对 logs 恒 false。
  - 前端 `FeedbackPage.downloadLog` 当时**只发 `Authorization: Bearer`，未带 `X-Service-Token`** → 即便后端开了旁路也不触发。
  - 内部路由 `internal/log-files`（router.go:56）用 `InternalDownload(ownerRestricted=false)`，与浏览器无关。
- 修复：
  - 后端：`router.go:23` 改为 `NewFileHandler(fileService, service.LogUploadPolicy(maxLogFileSize), logger, serviceToken, true)`（对齐 feedback 处理器），并加注释。源码在 develop-hy `/root/sproj/starland/apps/fileupload`；`make build` → `bin/fileupload` → scp 到 develop-tg `/opt/fileupload/bin/fileupload`（备份 `fileupload.bak-<ts>`）→ `systemctl restart fileupload`（health 200）。
  - 前端：`FeedbackPage.tsx` 的 `downloadLog` 注入 `config.fileServiceToken` 到 `X-Service-Token` 头（与 `fetchFeedbackImageBlob` 一致）。`tsc`/`vite build` 通过，部署 develop-tg + reload。
- 验证（probe_log.mjs 走 develop-tg openresty 真实路径）：修复前 [A]Bearer only=404、[B]Bearer+ServiceToken=404；修复后 [A]=404（owner 无令牌仍拦，符合预期）、[B]=200 application/zip。**证明 openresty 透传 X-Service-Token 头**。
- 经验：fileupload 的 owner 隔离对所有「跨 owner 读取」端点（log-files / feedback-files）都生效，后台取他人资源**必须**后端 handler 开 `allowServiceBypass=true` **且** 前端带 `X-Service-Token`，二者缺一不可。新增此类下载入口时务必对称处理。
