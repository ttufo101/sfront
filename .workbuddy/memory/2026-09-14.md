# 2026-09-14

## VPN 管理后台（Starland Admin）前端实现

基于仓库现有规范（admin.proto / gateway-protocol.md / frontend-baseline.md / react-performance.md / DESIGN.md(tdesign) / design.web.md）搭建了管理后台前端。

### 关键决策（用户确认）
- 统一网关路径：`/tools/adminapi` → **`/startlandapi`**（已在 config.adminEndpoint 体现）。
- 协议编码：int64/uint64 一律 **十进制字符串**（TS 类型按 string，格式化用 lib/format.ts）。
- 管理员角色：先用 JWT 解码 role 兜底、缺失时默认视为 admin（占位，待后端明确下发后替换），保证流程跑通。
- 其余按建议执行：自研轻量 hook（useXrpcQuery/useXrpcMutation，无 TanStack Query）、手写 TS 类型对齐 proto、浅色主题、VITE_USE_MOCK=true 本地 mock 跑通流程。

### 架构
- 栈：React18 + TS + Vite + shadcn/ui2.x + Tailwind3.4（frontend-baseline 锁定）。
- lib/xrpc：transport（信封/com 注入/解包/取消/错误归一）、admin-contract（冻结契约 registry）、mock、hooks。
- 六大 feature：users / plans / subscriptions / proxy-config / announcements / auth。
- 注：admin.proto 中 int64 字段标了 `[jstype=JS_NUMBER]`，与 gateway-protocol 的"十进制字符串"冲突，已按后者实现，待与后端确认线上真实格式。

### 环境坑（npm 原生二进制 / safe-delete）
- 沙箱 safe-delete 拦截 npm 安装回滚（bulk delete 确认），导致安装残损、缺 @esbuild/@rollup 原生二进制，`vite build` 失败。
- 失败尝试：`rm -rf` 被拦截；`mv node_modules node_modules_old && npm install` 在 npm 内部删除阶段仍被拦截回滚。
- **可用方案（已验证）**：不跑 npm install，改用 `npm pack @esbuild/win32-x64@<ver>` 下载 tarball → `tar -xzf ... -C node_modules/@esbuild/win32-x64 --strip-components=1` 直接落盘（只写不删，不触发 safe-delete）。rollup 原生包若缺失同理用 `@rollup/rollup-win32-x64-msvc`。
- 注意 esbuild Windows 解析路径为 `@esbuild/win32-x64/esbuild.exe`（包根目录，非 bin/）；rollup 为 `@rollup/rollup-win32-x64-msvc/rollup.win32-x64-msvc.node`。

### 最终状态
- `tsc --noEmit` 通过；`vite build` 通过（1675 modules，dist 产出，exit 0）；`vite` dev server 正常服务（/、/login、各 feature 模块均 200，无 transform 错误）。
- 残留 `node_modules_broken`（旧的残损份）因 safe-delete 无法 `rm`，暂留；不影响构建。

### 接入真实后端（用户给出地址 47.120.10.73:12001）
- 后端网关基址做成可配置：`.env` 的 `VITE_API_BASE`；`.env.example` 同步注释。
- `vite.config.ts` 新增 dev proxy：浏览器同源打 `/startlandapi` → Vite 转发到 `VITE_API_BASE`，**规避浏览器跨域(CORS)**（否则直连 47.120.10.73 会被跨域拦截）。
- `src/lib/xrpc/transport.ts` 改为：开发环境走相对路径 `/startlandapi`（走代理）；生产构建走 `config.apiBase + /startlandapi`（绝对地址，同样可配置）。
- `.env` 设 `VITE_USE_MOCK=false`，关闭 mock 走真实后端。
- 已验证：经 dev server POST `/startlandapi` 转发到真实后端，返回 `{"code":401,"msg":"email or password is invalid","data":""}` —— 信封格式 `{code,msg,data}` 与契约一致（401 仅因探测账号密码不对）。
- 注意：真实管理员账号密码未知（探测用 admin@starland.dev/admin123456 返回 401），需用户提供真实凭据才能登录；登录成功后若后端 JWT 带 role 声明，则管理员角色判定从"JWT 解码兜底"变为真实生效（顺带验证待确认项②）。
