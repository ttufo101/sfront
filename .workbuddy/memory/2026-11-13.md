## 发现的三处缺陷（未修，待用户决定）
1. **心跳复活不清离线残留**：`HeartbeatNode` 的 SET 缺 `offline_at=NULL, offline_reason=''`，WHERE 也不带 runtime_status 条件，故 offline 节点靠心跳可直接复活但残留旧离线信息。实测两节点 online 却仍带 11-11 17:38:36 `heartbeat_timeout`；前端仅在 `runtime_status==='offline'` 时展示离线信息，把残留藏住了。最小修复：在 HeartbeatNode 的 SET 补两列（与 MarkNodeOnline 对齐）。
2. **阈值双口径**：后端 45s 判 offline，前端 `isAssignable` 用 300s 判断心跳有效。正常路径下前端阈值冗余（后端先拦），真正价值是 dataplane 整体挂掉/sweep 停摆时兜底「可分配」，但「运行状态」列仍会冻结显示在线，有误导。日志佐证 11-11 17:35~17:38 sweep 连续 `context deadline exceeded` 失败。
3. **stale boot id 无自愈**（代码路径推断）：Heartbeat 返回 409 时 `lifecycleLoop` 只打日志、不把 `online` 置回 false，因此不会重发 `NodeOnline`；若 DB 中 boot_id 与运行进程不一致（手工改库/DB 恢复），节点会一直 409 且永不重新上线，需重启 Mihomo。最小修复：收到 stale 时重置 `online=false`。
