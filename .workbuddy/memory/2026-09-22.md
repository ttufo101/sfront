## HTTP 非安全上下文下的 Web Crypto 兼容修复（2026-09-22 后续）
- 用户截图：登录页报错 `crypto.randomUUID is not a function`。
- 根因：当前生产部署走 HTTP（80 端口，无证书），`crypto.randomUUID()` 与 `crypto.subtle` 只在安全上下文（HTTPS/localhost）可用。
- 修复：
  1. `src/lib/utils.ts` 新增 `uuidV4()`：优先 `crypto.randomUUID()`，不存在则回退到 RFC 4122 v4 手动实现。
  2. `src/lib/xrpc/transport.ts`：`getDevId()` 改用 `uuidV4()` 生成设备 ID，不再直接调用 `crypto.randomUUID()`。
  3. `src/lib/upload/sha256.ts`：`computeSha256()` 先检测 `crypto.subtle` 是否存在；不存在则回退到纯 JS SHA-256（RFC 6234），已用 Node `crypto.createHash` 对空串/abc/hello world/fox/1MB a 等用例验证结果一致。
  4. `sha256.ts` 原 `uuidV4` 改为从 `utils.ts` 导入并 re-export，避免重复实现。
- 构建：`npm run build` 通过（tsc + vite）。
- 部署：重新 `scp -r dist/*` 到 develop-tg `/opt/starland-admin-web/`，`nginx -t` 通过。
- 备注：HTTP 仅为临时方案（443/HTTPS 待证书）；长期仍建议启用 HTTPS，以彻底避免安全上下文限制。

## 发布 409 修复：expected_release_id 乐观锁（2026-09-22 后续）
- 现象：发布页报「发布失败：HTTP 409」。网关日志定位：`PublishAppVersion → 409 "current release changed, build number did not increase, or release already exists"`。
- 根因：admin `PublishAppRelease` 事务内对 `t_starcore_app_version` `FOR UPDATE` 乐观锁，**要求 `expected_release_id` 必须等于该平台当前生效版本的 release_id**（`(hasCurrent && expected!=currentID)` 或 `(!hasCurrent && expected!="")` 即 ErrConflict）。android 已有生效版本 `rel_458c1a...`(0.2.0/build15)，而前端固定传 `expected_release_id: ''` → 必然 409。首发成功是因为当时该平台无生效版本。
- 修复：
  1. `ReleaseUploadPage.tsx`：发布前先 `listAppVersions({platform, include_history:false})`，取 `status==='active'` 的 `release_id` 作为 `expected_release_id`（无则留空）。
  2. `releases.ts` 重新加回 `listAppVersions` 包装（重新有了调用方，不再属于死代码）。
  3. `transport.ts` `postJson`：非 2xx 时先尝试解析响应体 `{code,msg}`，取业务消息作错误消息，不再只显示 "HTTP 409"。
- 构建通过（425.05 kB），已部署 develop-tg 并清理远端旧产物，`GET /` 200。
- 相关后端事实（备查）：409 的三个触发条件都在 store 层（`data.go PublishAppRelease`）：① expected_release_id 不匹配；② build_number ≤ 当前值；③ 新版本号 < 当前版本号；④ INSERT 撞唯一键（file_id/client_request_id/release_id 唯一）。`t_admin_app_release` 仅 1 条旧记录，其 `update_url` 仍是老的 `https://download.starland.example/...`（发布早于 public_base_url 修改）。
- 修复后用户重新发布成功：android 0.4.0 / build 35 变为 active，旧 0.2.0 变 superseded（**历史记录确实保留**，非覆盖）。
